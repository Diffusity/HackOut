# ADR-022: Custom ML Risk Explainability and Training Workflow

## Context
As part of the hackathon, we need to demonstrate advanced technical capabilities while ensuring transparency and fairness in AI decisions for banking customers. The existing system uses deterministic rules for credit decisions, but we want to enrich the experience with a predictive ML model for risk scoring.

## Decision
We implemented a custom, from-scratch Logistic Regression model to predict the probability of a missed EMI. This model is strictly advisory and never overrides the deterministic rule engine.

To ensure transparency and explainability:
1. **Interactive Training UI**: We added a `ModelTrainer` component that allows users to upload synthetic transaction datasets and retrain the model on the fly using gradient descent.
2. **Explainability Modal**: We built a `RiskExplainabilityModal` that exposes the global feature weights (coefficients) of the logistic regression model, showing exactly how factors like savings rate, income volatility, and EMI burden influence the score.
3. **Fraud-Alert Toast**: We integrated real-time anomaly detection alerts on the dashboard to immediately notify staff when a high fraud risk score (> 80) is detected.

## Status
Accepted.

## Consequences
- **Positive**: High transparency, verifiable explainability, and interactive ML capabilities greatly enhance the project's appeal for hackathon judges.
- **Negative**: The model is trained from scratch in TypeScript, which is not optimized for large-scale data, but is sufficient for a hackathon demonstration.
